# 결정과 근거

앱을 고치면서 같이 정리한 판단들입니다. 코드보다 오래 남을 내용만 적었습니다.

---

## 1. 베타는 30가구 4주

처음엔 “15가구 2주 → 고치기 1주 → 50가구 4주”로 잡았습니다.
2주로 끊은 이유는 **빨리 고쳐서 다음 그룹에 더 나은 걸 주자**는 것이었습니다.

**그 이유가 사라졌습니다.** 30가구를 한 번에 가기로 했고, 그러면 “다음 그룹”이 없습니다.
그리고 웹앱이라 고치는 즉시 반영됩니다 — 멈췄다 다시 시작할 이유가 없습니다.

**2주는 “신기함” 구간입니다.** 어떤 앱이든 첫 2주는 다 씁니다.
진짜 갈림은 3~4주차입니다. 2주에서 끊으면 “다들 잘 쓰네”라는 착각만 얻습니다.
알림을 켠 집과 안 켠 집의 차이도 2주엔 안 벌어집니다. 아직 안 까먹을 때니까요.

그리고 지원사업·경진대회 서류의 표준은 **4주 유지율**입니다. 2주짜리 숫자는 못 씁니다.

### 4주를 이렇게 씁니다

| | 무엇 | 손대기 |
|---|---|---|
| 1주차 | 버그 폭탄 구간 | 매일 고치고 배포 |
| 2주차 | 중간 설문 · 안 쓰는 기능 확인 | 계속 고침 |
| 3~4주차 | **유지율 관찰** | **큰 변경 금지** |

3~4주차에 화면 구조나 흐름을 바꾸면, 유지율이 떨어졌을 때
**제품 때문인지 내가 바꿔서인지 알 수 없게 됩니다.** 작은 버그 수정만 합니다.

### 봐야 할 숫자는 넷

1. 4주 유지율
2. 알림 켠 집 비율
3. **알림 켠 집과 안 켠 집의 유지율 차이** ← 이 앱의 존재 이유를 증명하는 숫자
4. 안 쓰는 기능 (“없어도 되는 것”을 고르게 물어야 순위가 나옵니다)

1~3은 앱이 자동으로 셉니다(설정 → 베타 지표). 4는 종료 설문에서 묻습니다.

### 조건 하나

**모르는 사람이 대부분이어야 합니다.** 아는 사람은 안 쓰면서도 좋다고 말해줍니다.
30가구는 거의 모르는 분들로 채웠습니다 — 그래서 나오는 숫자를 그대로 믿을 수 있습니다.

비용은 30가구 × 약 840원 = **월 2만 5천원**입니다.

## 2. 개인정보 — 짚어봐야 할 것

말씀하신 기능 중 법적으로 무게가 다른 것들이 섞여 있습니다.

### 민감정보에 해당하는 것 (개인정보보호법 제23조)

**건강 정보는 별도의 명시적 동의가 필요합니다.** 일반 동의에 묻어갈 수 없습니다.

- **부인 몸 컨디션** — 좋아요/보통/힘들어요는 건강 상태 기록입니다. 게다가 부부 공유라
  “당신 어제 힘들다고 했잖아”가 가능해집니다. 걱정하신 게 맞습니다.
  → **설정에 “가족에게 보이기” 스위치를 넣었습니다.** 끄면 나만 봅니다.
  → 정식 서비스로 가면 이 항목은 **가입 시 동의를 따로 받고, 기록은 당일치만 남기고 지우는 게** 안전합니다. 지금은 날짜 하나만 저장하고 이력을 쌓지 않습니다.
  → “계속 아프다고 하면 어떡하나” — 앱이 판단할 문제가 아닙니다. 3일 연속 ‘힘들어요’면
     목록을 줄이는 것까지가 앱의 몫이고, 그 이상은 하지 않는 게 맞습니다.
- **예방접종·병원·약 기록** — 아이와 부모님 것 모두 건강정보입니다.
  지금은 “예방접종 확인하기” 같은 **할 일 제목만** 저장하고 접종 이력 자체는 저장하지 않습니다.
  이 선을 넘지 마세요. 넘는 순간 의료정보 취급 기준이 따라옵니다.

### 만 14세 미만 아동 정보 (제22조의2)

- 아이 이름·나이·유치원 정보는 **법정대리인 동의**가 필요합니다.
  부모가 직접 넣는 구조라 실질적으로는 충족되지만, 개인정보처리방침에 그 근거를 적어두세요.
- **아이 이름은 별명으로 충분합니다.** “첫째”가 기본값인 건 그래서입니다. 실명을 권하지 마세요.

### 알림장 사진 스캔 — 가장 조심할 부분

알림장에는 **우리 아이 정보만 있는 게 아닙니다.** 다른 아이 이름, 담임 선생님 이름,
전화번호, 반 전체 공지가 같이 찍힙니다. 이건 **제3자의 개인정보**입니다.

지금 구현에 넣은 안전장치:
- 사진을 1200px로 줄여 **EXIF(위치·기기 정보)를 떼고** 보냅니다.
- 사진은 **앱에 저장하지 않습니다.** AI에 한 번 보내고 버리고, 뽑아낸 할 일만 남습니다.
- 프롬프트에 **“개인 이름은 옮기지 마세요”**를 넣었습니다.
- 서버 로그에 사진과 프롬프트를 남기지 않습니다.

그래도 남는 위험이 있습니다. Anthropic API로 전송은 됩니다.
→ 개인정보처리방침에 **“AI 처리를 위해 국외(미국)로 이전됨”**을 반드시 적어야 합니다 (제28조의8).
→ 베타 안내문에 한 줄 더: “사진에 다른 아이 이름이 보이면 가리고 찍어주세요.”

### 안전한 편인 것

- 집안일 목록, 주기, 담당자, 장바구니 — 민감하지 않습니다.
- 자동차 주행거리·연비 — 개인정보이긴 하나 민감정보는 아닙니다.
- 관리비 납부일 — 단지를 특정할 수 있지만 날짜만으론 무리입니다.

### 지금 당장 해야 할 것

1. **개인정보처리방침 페이지**를 만드세요. 베타라도 필요합니다. 최소 항목:
   수집 항목 / 이용 목적 / 보관 기간 / **국외 이전(Anthropic, 미국)** / 파기 방법 / 문의처.
2. 베타 참가 동의서에 **컨디션·아이 정보·사진 스캔**을 따로 체크하게 하세요.
3. 베타가 끝나면 **참가자 데이터를 지운다는 약속과 실제 삭제**를 하세요.
   설정의 ‘데이터 전체 삭제’가 그 창구입니다.

## 3. 제휴는 어떤 식으로 붙는가

### 지금 붙어 있는 것

`index.html`의 `LINKS` 배열 한 곳에 모아뒀습니다. 태그가 세 종류입니다.

- **정보** — 공공기관. 예방접종도우미, 아이사랑, 정부24, 아이돌봄서비스, 가족센터,
  학교알리미, 오피넷, 자동차민원포털. **대가가 없어서 표기 의무도 없습니다.**
- **추천** — 민간 서비스인데 돈을 안 받는 상태. 쿠팡, 만개의레시피, 유튜브 검색,
  아자스쿨, 놀이의발견, 키즈노트, 이사 견적.
- **광고** — **대가를 받으면 반드시 이걸로 바꿔야 합니다.** 표시광고법 위반은 과징금 대상이고,
  “제휴”라고만 써도 부족합니다. 쿠팡 파트너스를 붙이는 순간 이 태그로 바꾸세요.

한 자리에 **최대 2개**만 뜹니다. 광고판처럼 보이면 앱을 안 씁니다.

### 물어보신 것들에 대한 답

- **아이돌봄센터·문화센터 연결** — 지역마다 운영 주체가 달라서 전국 API가 없습니다.
  정부 아이돌봄서비스와 가족센터(전국 단위)로 보내는 게 현실적입니다.
  “우리 동네”는 지도 검색으로 넘기는 게 낫습니다. 직접 DB를 만들면 관리가 안 됩니다.
- **키즈노트 제휴로 준비물 자동** — 제휴가 되면 가장 좋습니다. 다만 알림장 데이터는
  어린이집이 주체라 **회사 간 계약만으로 안 되고 원의 동의가 필요할 가능성**이 높습니다.
  그래서 **사진 스캔을 먼저 넣었습니다.** 제휴 없이 오늘 되는 방법이고, 제휴가 되면 그때 바꾸면 됩니다.
- **유튜버 제휴** — 개인 유튜버와 계약하면 그 사람이 채널을 접었을 때 링크가 죽습니다.
  지금은 **검색어를 넘기는 방식**입니다. 제휴를 하시려면 채널 하나가 아니라
  “레시피 카테고리 몇 개”를 다루는 MCN과 하시는 게 낫습니다.
- **꼭 한 개일 필요는 없다** — 동의합니다. 그래서 `LINKS`는 배열이고 조건에 맞는 걸
  최대 2개까지 보여줍니다. 셋 이상은 고르기 싫어집니다.

### 붙일 때 순서

1. 링크 클릭 수를 먼저 보세요 (`설정 → 베타 지표 → 제휴 링크 클릭`).
2. 클릭이 실제로 나오는 자리에만 제휴를 제안하세요. 클릭 0인 자리는 협상 카드가 없습니다.
3. 계약이 되면 `LINKS`의 해당 항목에서 `tag`를 `"광고"`로 바꾸고 URL에 제휴 코드를 넣으세요.

## 4. 장보기·냉장고 — 직접 만들지 않고 연결한다 (방향 변경)

처음엔 앱 안에 장바구니를 만들었다가 뺐습니다. 이유는 단순합니다.
**장바구니·재고·유통기한 관리는 그 자체로 앱 하나 분량**이고, 이미 잘하는 앱이 많습니다.
어설프게 반쪽짜리를 들고 있으면 유지보수만 늘고, 사용자는 어차피 쓰던 앱을 씁니다.

먼저ON이 맡는 선:
1. **“사야 한다”는 사실을 기억하는 것까지** — 살 것은 status "buy"인 할 일로 남습니다.
2. 사는 행위와 재고 관리는 **바깥으로 연결** — 구매성 할 일 밑에 쿠팡 검색이,
   냉장고·식단 관련에는 냉장고 관리 앱·만개의레시피·유튜브 레시피 카드가 붙습니다.
3. 냉장고 사진 스캔은 유지 — 재고 앱을 안 쓰는 집을 위한 가장 낮은 문턱입니다.

닫힌 앱을 깨우는 진짜 푸시는 서비스워커 + Web Push + 서버 스케줄러가 필요합니다.
30가구 베타에서는 굳이 필요 없고, 100명으로 갈 때 넣는 게 순서에 맞습니다.
그때 보낼 알림은 딱 셋으로 좁히세요: **넘어온 일 / 오늘 안 하면 늦는 일 / 휴일 브리핑.**
그 외에 보내면 알림을 통째로 끕니다.

## 5. 비슷한 앱이 있나 — 경쟁 지형 (2026-08 확인)

**해외에는 카테고리가 이미 있다.** "mental load"가 마케팅 언어로 쓰일 정도.
- Tody — 방·항목별 청소 주기를 정하면 밀린 순서로 보여줌. "기억 안 해도 되게"의 원형.
- Sweepy — 같은 컨셉 + 점수·리더보드로 가족 분담을 게임화.
- Ohai.ai — AI 가정 비서 (일정 동기화·위임·스마트 알림). 컨셉상 가장 근접.
- OneHaus, Maple 등 — 분담·로테이션 중심의 가족 앱들.

**한국에는 사실상 없다.** 루티너리(개인 습관), 집안일관리·홈 태스커(가족 공유
체크리스트) 정도이며 전부 사용자가 목록을 직접 만들어야 한다. 노션으로 직접
짜서 쓰는 사람이 많다는 것이 기성 앱의 공백을 보여준다.

**차별점 = 세팅의 주체가 다르다.**
1. 목록을 고르는 게 아니라 가구 질문 몇 개(아이 나이·차·반려동물)로 목록이 조립됨
2. 등록 안 한 일도 생애주기로 선제 제안 (아이 나이 역산 — Tody류가 구조적으로 못 함)
3. 말로 쏟아내면 AI가 분류·등록. 알림장·냉장고는 사진으로
4. 한국 살림 목록: 제사(음력)·관리비 납부일·알림장·명절 준비

이 절의 근거 링크는 대화 기록의 검색 결과 참조.

## 6. 이알리미·키즈노트 자동 확인 — 로드맵

원하는 그림: AI가 이알리미를 이틀에 한 번 확인해서 준비물을 알아서 담아주기.
맞는 방향인데, 지금 못 넣는 이유가 셋 있다.

1. **공식 API가 없다.** e알리미·키즈노트 모두 외부 조회 API를 열어두지 않아서,
   자동 확인은 학부모 계정으로 대신 로그인하는 방식이 된다.
2. **비밀번호를 우리가 보관해야 한다.** 이건 알림장 사진과는 차원이 다른 보안 부담이다.
   유출 시 아이 소속 기관·실명이 통째로 노출된다.
3. **서버 상주 작업이 필요하다.** 이틀마다 확인하려면 크론 서버 + 세션 유지가 필요하다.

그래서 순서: **지금은 사진 스캔** (알림장이 오면 캡처 한 장 → AI가 할 일만 추출.
이미 구현됨) → **베타에서 스캔 사용률 확인** → 수요가 증명되면 키즈노트 쪽과
제휴 협의(원 동의 필요)로 정식 연동. 대리 로그인 방식은 하지 않는다.

## 7. 알림(웹 푸시) — 왜 이렇게 만들었나

**알림이 앱의 본체다.** 타깃은 "잘하는 사람"이 아니라 **잘 까먹는 사람**이다.
앱을 열어야만 보이는 정보는 까먹는 사람에게 도달하지 않는다. 그래서 앱을 닫아둬도
잠금화면까지 가는 웹 푸시로 간다.

**알림톡이 아니라 웹 푸시인 이유.** 카카오 알림톡은 3,000건에 월 3만 원 정도가
계속 나간다. 웹 푸시는 0원이다. 30가구 베타에서 유료 채널을 켤 이유가 없다.

**보내는 규칙**
- 매시 정각에 서버가 돌면서, 지금이 그 집이 고른 시각인 구독에만 보낸다
- **그날 챙길 게 없으면 아예 안 보낸다.** 매일 오는 빈 알림만큼 앱을 지우게 만드는 게 없다
- 하루 한 번. 그 이상 보내지 않는다
- 알림 내용(할 일 제목)은 서버 로그에 남기지 않는다 — 개인정보다

**매일 루틴이 알림에 들어가야 한다.** "개 산책"처럼 매일인데 매일 까먹는 일이
정확히 이 앱이 존재하는 이유다. 그런데 루틴은 `st.tasks`에 없고 씨앗 목록에서
계산되는데, 알림 서버는 씨앗 목록을 모른다. 그래서 앱이 `st.routineTitles`
(루틴 key → 제목)를 적어두고 서버는 그것만 읽는다.

**"하던 대로면 충분해요"를 뺐다.** 루틴을 접어둘 때 쓰던 문구인데,
매일 하는 일을 매일 까먹는 사람에게는 **틀린 말이고 놀리는 것처럼 들린다.**
대신 남은 개수와 **이름**을 보여준다 — 접혀 있어도 "개 산책"이 눈에 들어와야 한다.
칭찬 문구는 앞으로도 쓰지 않는다.

**아이폰은 홈 화면에 추가해야만 된다.** 애플이 그렇게 막아놨다. 그냥 실패시키면
"안 오네" 하고 끝나므로, 막혔을 때 추가하는 순서를 그 자리에 펼쳐 보여준다.
네이버·카카오 앱 안 브라우저에서는 아예 못 켜는 것도 미리 알려준다.

### service_role 키 — 규칙에서 벗어난 곳 (의도적)

기존 원칙은 "service_role 키는 절대 쓰지 않고 anon만 쓴다"였다.
**`api/push-send.js` 한 곳만 예외로 둔다.**

- 이유: 알림을 보내려면 로그인한 사람이 없는 새벽에 **모든 가구의 오늘 할 일**을
  읽어야 하는데, anon 키는 로그인한 본인 것만 읽을 수 있다
- 안전장치: 이 함수는 `CRON_SECRET` 없이는 아무도 못 부르고, 키는 Vercel
  환경변수에만 있으며 브라우저로는 절대 내려가지 않는다 (`api/config.js`는 공개 키만 내보냄)
- 대안(security definer 함수 + DB에 별도 비밀번호)은 부품이 하나 늘고 비밀이
  DB로 들어가서, 30가구 규모에서 얻는 게 없다고 판단했다

**→ 베타 후속 검토 항목.** 가구 수가 늘면 다시 본다.
그때 볼 것: 읽는 범위를 "오늘 보낼 구독이 있는 가구"로 더 좁힐 수 있는지,
security definer 함수로 옮길 값어치가 생겼는지.
