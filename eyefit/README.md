# 렌즈값 계산기 — "내 도수에 정말 그 렌즈가 필요한가"

안경원에서 더 비싼 렌즈를 권할 때, 소비자에게는 그게 맞는 말인지 판단할 근거가 없습니다.
그런데 **렌즈 두께는 도수와 테 치수만 알면 광학 공식으로 계산됩니다.**

이 도구는 그 계산을 대신 해서, 굴절률을 올릴 때 **몇 mm를 위해 얼마를 더 내는지**를
숫자로 보여줍니다. 결론만 주지 않고 계산식까지 전부 공개합니다.

> **폴더 이름 `eyefit/`은 과거 이름입니다.** 이 프로젝트는 원래 "얼굴에 맞는 안경 추천 +
> 맞춤 제작 + 안경원 연결" 앱이었는데, 조사해보니 그 전부가 이미 있었습니다(브리즘, 라운즈,
> Topology, YOU MAWO). 아무도 안 하던 한 가지 — **렌즈 값 투명화** — 로 좁혔습니다.
> 옛 기능은 커밋 `8d6d518`에 그대로 남아 있습니다. 자세한 경위는 앱의 `/landscape` 페이지에.

## 왜 이 방향인가

- **제휴 없이 1일차부터 동작합니다.** 렌즈 두께는 계산되는 값이라 제휴 안경원이 0곳이어도
  결과가 나옵니다. 가격 비교 서비스가 데이터 없이 못 굴러가는 문제를 피합니다.
- **경쟁 서비스가 전부 테를 다룹니다.** 라운즈는 테 커머스, 브리즘·Topology·YOU MAWO는
  테 제조입니다. 렌즈를 건드리는 곳은 없습니다.
- **소비자가 실제로 판단 못 하고 돈을 더 내는 지점이 렌즈입니다.**

## 무엇을 계산하는가

### 1. 렌즈 두께는 새그(sagitta)로 정해집니다

```
s = r − √(r² − h²)            (곡면의 처짐)
r[mm] = (n − 1) × 1000 / |F|   (도수 F, 굴절률 n에서의 곡률 반지름)
```

굴절률이 높을수록 r이 커지고(면이 완만해지고) 새그가 작아져 렌즈가 얇아집니다.
흔히 쓰는 `h²/2r` 근사식은 도수가 높고 렌즈가 크면 오차가 커져서 쓰지 않았습니다.

근시는 중심 두께를 1.2mm로 고정하고 가장자리가 두꺼워지고, 원시는 반대입니다.

### 2. h는 테 치수와 PD에서 나옵니다

```
편심 = (렌즈폭 + 브릿지 − PD) / 2
h = √( (렌즈폭/2 × 0.92 + 편심)² + (세로폭/2 × 0.92)² )
```

테의 광학중심 간격이 PD보다 넓으면 렌즈를 코 쪽으로 편심시켜 깎고, 그만큼 바깥쪽이
두꺼워집니다. `0.92`는 실제 렌즈가 사각형이 아니라 모서리가 둥글게 깎이는 것을 반영한
보정입니다. 난시가 있으면 `SPH`와 `SPH+CYL` 중 절댓값이 큰 경선을 씁니다.

### 3. 추천 규칙

싼 굴절률부터 훑으면서 **둘 중 하나라도** 만족하는 첫 번째를 고릅니다.

1. 테 안에 숨을 만큼 얇거나 (풀테 5mm / 하금테 3.5mm / 무테 3mm 이하)
2. 더 올려봐야 **0.5mm 미만**밖에 안 얇아지거나

둘을 **OR**로 묶은 게 중요합니다. 목표 두께만 쓰면 아슬아슬하게 넘길 때 가장 비싼 렌즈로
튀어버리고, 차이만 쓰면 아주 두꺼운 렌즈를 그냥 넘깁니다.

결과는 실제 안경원 관행과 거의 일치합니다 (50□18 h38, PD 63 기준):

| 도수 | 추천 | 가장자리 두께 |
| --- | --- | --- |
| −1.00 ~ −4.00 | 1.56 | 2.1 ~ 4.7mm |
| −4.50 | 1.60 | 4.8mm |
| −5.00 ~ −6.50 | 1.67 | 4.8 ~ 6.0mm |
| −7.00 이상 | 1.74 | 5.8mm ~ |

### 4. 무게 — 얇다고 가볍지 않습니다

| 굴절률 | 밀도 (g/cm³) |
| --- | --- |
| 1.56 | 1.28 |
| 1.60 | 1.30 |
| 1.67 | 1.36 |
| 1.74 | 1.47 |

굴절률이 높은 재료일수록 밀도도 높아서, 1.74로 올려도 얇아진 만큼 가벼워지지 않습니다.
결과 화면에 무게를 함께 띄우는 이유입니다.

## 화면

- **`/check`** — 도수 + 테 치수 + 생활환경을 넣으면 결과가 즉시 갱신됩니다.
  굴절률별 렌즈 단면을 **가로세로 같은 배율**로 그려서, 0.4mm 차이가 눈에 보이는지
  직접 판단하게 합니다. "테를 4mm 작은 걸로 바꾸면 굴절률 한 단계보다 더 얇아진다"는
  비교와, 코팅별 필요/선택/근거 약함 판정, 매장에서 물어볼 질문 목록이 함께 나옵니다.
- **`/quotes`** — 실제로 낸 렌즈 값 제보와 굴절률별 분포(중앙값·사분위). 제보가
  5건 미만이면 통계를 보여주지 않습니다.
- **`/how-it-works`** — 계산식과 가정, 그리고 **이 계산이 못 하는 것**을 전부 공개합니다.
- **`/landscape`** — 경쟁 서비스 조사와 왜 이 방향으로 좁혔는지.

## 개인정보

**도수를 저장하지 않습니다.** 계정도 없습니다.

- 두께 계산은 **브라우저 안에서** 끝납니다. 도수를 직접 입력하면 서버로 아무것도 가지 않습니다.
- 처방전 사진으로 자동 입력할 때만 판독 서버를 한 번 거치고, 그 이미지는 응답과 함께
  버려집니다 (`dynamic = "force-dynamic"` + `Cache-Control: no-store`).
- DB에 남는 건 금액 제보뿐이고, 거기에도 **도수는 받지 않습니다** — 지역·매장유형·굴절률·
  옵션·금액만 남습니다. 도수는 민감정보라, 목적에 필요 없으면 아예 만들지 않는 게 맞습니다.

## 한계 (앱 안에도 그대로 적어뒀습니다)

- 제조사별 렌즈 설계(비구면, 베이스커브)를 반영하지 못합니다.
- 테 모양을 렌즈폭×세로폭 사각형에 계수를 곱해 근사합니다. 특이한 모양은 오차가 큽니다.
- 누진렌즈 두께는 설계에 따라 크게 달라져서, 이 계산은 단초점 기준입니다.
- 코팅 효능 판단은 일반적인 연구 동향 요약이지 의학적 조언이 아닙니다.

목적은 "안경사보다 정확한 값"이 아니라, 매장에서 **같은 단위로 대화할 기준**을 만드는 것입니다.

## 기술 스택

Next.js 14 (App Router) + TypeScript + Tailwind CSS / Prisma + PostgreSQL(금액 제보만) /
OpenAI 비전 모델(처방전 판독)

## 로컬 개발

```bash
cd eyefit
npm install
cp .env.example .env       # OPENAI_API_KEY는 처방전 자동 판독에만 필요 (없어도 동작)

docker compose up -d       # 로컬 Postgres (localhost:5433)
npm run db:push
npm run dev                # http://localhost:3000
```

OpenAI 키가 없어도 앱은 정상 동작합니다. 도수를 직접 입력하는 경로가 주 경로이고,
그 경우 도수는 브라우저 밖으로 나가지 않습니다.

## 배포 (Vercel)

1. [vercel.com/new](https://vercel.com/new)에서 `choiyeonah-hub/yeonah` Import
2. **Root Directory를 `eyefit`으로 지정** (저장소 루트는 별개 프로젝트인 하브루타 톡입니다)
3. 환경변수: `POSTGRES_PRISMA_URL`, `POSTGRES_URL_NON_POOLING`, `OPENAI_API_KEY`(선택),
   `OPENAI_VISION_MODEL`(선택)
4. Deploy. `vercel-build`가 매 배포마다 `prisma db push`로 스키마를 맞춥니다.
