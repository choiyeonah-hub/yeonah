# 아이핏 (EyeFit) — 얼굴에 맞는 안경 찾기

얼굴 사진과 안경 처방전을 읽어서 **테 + 렌즈**를 함께 추천하고,
기성품에서 고르거나 **제휴 공장에 맞춤 제작**을 넣은 다음,
동네·전국 안경원의 예상 견적을 비교해 **방문 예약**까지 하는 앱입니다.

같은 저장소의 `하브루타 톡`(저장소 루트)과는 **완전히 별개의 프로젝트**입니다.
의존성, DB, 배포가 모두 따로 굴러갑니다.

## 왜 만들었나

시중 안경 사이즈 규격은 서구권 두상을 기준으로 만들어진 게 많습니다. 코받침이 낮아
흘러내리거나, 전체폭이 커서 관자놀이에 안 맞는 일이 그래서 생깁니다. 아이핏은
성별이나 인종을 전제한 "표준 두상"을 쓰지 않고 **사진에 보이는 실제 비율**로 계산하고,
기성품이 안 맞으면 **그 치수로 새로 만듭니다**.

성별을 묻지 않고 외모 점수도 매기지 않으며, 누구나 같은 방식으로 씁니다.

## 다섯 단계

1. **얼굴 비율 재기** — 사진 한 장으로 얼굴형(8종)·얼굴폭·콧대 높이·눈 간격·눈썹 라인을
   측정합니다. 사진을 올리기 싫으면 얼굴형을 직접 골라도 끝까지 진행됩니다.
   옆모습을 한 장 더 올리면 **콧대 높이를 mm로** 잽니다.
2. **도수 읽기** — 안과·안경원 처방전을 찍어 올리면 SPH / CYL / AXIS / ADD / PD를 읽어
   채워줍니다. 직접 입력해도 되고, 도수를 몰라도 "매장에서 검안"으로 넘어갈 수 있습니다.
3. **테 정하기** — 두 갈래가 있습니다.
   - **기성품**: 아래 다섯 축을 합산해 0~100점의 적합도를 매기고 순서대로 보여줍니다.
   - **맞춤 제작**: 얼굴 계측값에서 치수를 직접 뽑아 제휴 공장에 발주합니다.
4. **렌즈 고르기** — 실효 도수(|SPH| + |CYL|/2)로 굴절률(1.56 / 1.60 / 1.67 / 1.74)을
   정하고, 화면 사용 시간·야외 활동으로 코팅을 제안합니다.
5. **가격 비교 · 예약** — 매장별 예상 견적을 싼 순으로 보여주고 6자리 코드를 발급합니다.

### 기성품 적합도 점수

| 축 | 배점 | 내용 |
| --- | --- | --- |
| 얼굴형 × 테 모양 | 40 | 대비 원칙 (둥근 얼굴엔 각진 테, 각진 얼굴엔 곡선 테) |
| 얼굴폭 × 테 전체폭 | 20 | 크면 흘러내리고 작으면 관자놀이에 자국이 남는다 |
| PD × 광학 중심 | 15 | 한쪽당 편심(decentration)이 작을수록 렌즈가 얇다 |
| 콧대 × 코받침 | 15 | 콧대가 낮으면 아시안핏 / 코패드 조절형 |
| 도수 × 테 구조 | 10 | 고도수는 좁은 렌즈폭 풀테가 두께를 덜 드러낸다 |

누진 처방인데 렌즈 세로폭이 34mm 미만이면 근용부가 안 들어가므로 크게 감점합니다.

### 사진에서 mm를 뽑는 법 — 홍채를 자로 쓴다

사진 속 길이를 실제 mm로 바꾸려면 기준자가 필요합니다. 신용카드를 얼굴에 대고 찍게 하는
앱도 있지만, 아이핏은 **홍채 가로 지름**을 씁니다. 사람의 각막 가로 지름은 개인차가 작아
평균 약 11.7mm라, 사진 안에 이미 들어 있는 자입니다.

```
mm = (사진 속 비율 / 홍채 비율) × 11.7
```

이렇게 **PD(동공 간 거리)**와 **얼굴 폭**을 mm로 뽑습니다. PD가 50~78mm, 얼굴 폭이
110~180mm 범위를 벗어나면 원근 왜곡이나 오독으로 보고 환산을 포기합니다. 나온 값은
참고용이고, 실제 안경을 맞출 PD는 매장에서 다시 잽니다.

**옆모습**을 추가로 올리면 정면만으로는 알 수 없는 세 가지를 잽니다.

| 잰 값 | 쓰는 곳 |
| --- | --- |
| 콧대 높이(mm) | 코받침 높이 = 16 − 콧대 높이. 안경이 흘러내리는지를 가르는 치수 |
| 콧대 경사각(도) | 코받침을 눕히는 각도 |
| 귀–눈 높이차(mm) | 템플을 꺾어 내리는 양. 안경이 한쪽으로 기우는 걸 막는다 |

### 가상 착용

얼굴 인식을 브라우저에서 다시 돌리지 않습니다. 얼굴 분석 때 이미 받아온 좌표(동공 두 개,
코받침 지점, 얼굴 좌우 끝, 홍채 지름)로 테를 사진 위에 얹습니다.

- 테 크기는 **실제 각인 치수(전체폭 mm)를 홍채 축척으로 환산**해 그리므로, 큰 테와 작은
  테의 차이가 화면에서도 그대로 보입니다.
- 두 동공을 잇는 선의 각도만큼 테를 기울여, 고개가 기운 사진에도 자연스럽게 얹힙니다.
- **사진은 브라우저 메모리에만 있고 다시 업로드되지 않습니다.** 가상 착용은 전부
  클라이언트에서 그려집니다.
- 색과 재질 질감은 표현되지 않습니다. 크기와 모양을 비교하는 용도입니다.

맞춤 제작에서도 같은 방식으로 "이 치수로 만들면 이렇게 됩니다"를 미리 보여줍니다.

### 맞춤 제작 치수 산출

기성품은 "정해진 사이즈 중 가장 가까운 것"을 고르는 일이지만, 맞춤 제작은 반대로
얼굴에서 치수를 만들어냅니다. 기성품에서 늘 어긋나던 두 치수를 먼저 확정합니다.

1. **테 전체폭** ← 사진에서 잰 얼굴 폭 − 2mm (사진이 없으면 좁음 130 / 보통 138 / 넓음 146)
2. **코받침 높이** ← 16 − 옆모습에서 잰 콧대 높이 (옆모습이 없으면 낮음 12 / 보통 9 / 높음 6)
3. 브릿지 ← 눈 간격 (+ 콧대가 낮으면 1mm 넓힘)
4. 렌즈 가로폭 ← (전체폭 − 브릿지 − 엔드피스 18) / 2
5. 렌즈 세로폭 ← 얼굴형 (긴 얼굴 44 / 둥근 얼굴 37), 누진이면 최소 36
6. 템플 길이 ← 얼굴 폭
7. 편심량 = (렌즈폭 + 브릿지 − PD) / 2 를 계산해 함께 알려줍니다

## 판매 주체가 둘로 나뉩니다

이 앱의 핵심 제약입니다. 「의료기사 등에 관한 법률」상 **도수 렌즈의 조제·판매는
안경사만** 할 수 있고, 안경사조차 전자상거래로는 팔 수 없습니다. 반면 **안경테 자체는
일반 공산품**이라 면허 없이 제조·판매할 수 있습니다. 그래서 역할을 이렇게 나눴습니다.

| 누가 | 무엇을 | 면허 |
| --- | --- | --- |
| 아이핏(플랫폼) | 계측 · 추천 · 맞춤 치수 설계 · 공장 발주 · **테 판매** | 불필요 |
| 제휴 공장 | 설계 치수대로 테 제작 | 불필요 |
| 제휴 안경원 | 최종 검안 · **렌즈 조제·판매** · 피팅 | 안경사 필수 |

코드도 이 구조를 따릅니다. 기성 테는 안경원 재고라 매장 할인이 붙지만(`frameDiscountable: true`),
맞춤 테는 플랫폼이 파는 물건이라 매장 할인이 붙지 않습니다. 앱에서는 결제하지 않습니다.

더 자세한 내용과 사업 시작 전 확인 목록은 앱의 `/how-it-works` 페이지에 있습니다.
**법률 자문이 아니므로 실제 사업 전에는 변호사 확인이 필요합니다.**

## 제휴 공장

공장을 고를 때 중요한 건 단가가 아니라 **1개를 만들 수 있는지**입니다.

| 공법 | 1개 제작 | 특징 |
| --- | --- | --- |
| SLS 3D 프린팅 (나일론) | 가능 | 금형이 없어 사람마다 다른 치수를 그대로 반영 |
| CNC 아세테이트 절삭 | 가능 | 색·무늬 선택지가 넓고 질감이 좋음 |
| 티타늄 판재 가공 | 가능 | 가장 가볍지만 단가가 높음 |
| 사출 성형 / 금속 프레스 | 불가 | 금형비와 최소 수량이 필요한 양산 전용 |

`src/lib/factories.ts`에 국내(대구 안경산업단지), 일본 사바에, 이탈리아 벨루노,
중국 원저우 공장을 데모 데이터로 넣어두었습니다. 실제 제휴 시 견적서를 받아
단가·최소 수량·리드타임만 갈아끼우면 나머지 계산은 그대로 동작합니다.

## 개인정보

- **얼굴 사진과 처방전 이미지는 저장하지 않습니다.** 요청을 처리하는 동안에만 메모리에
  있다가 응답과 함께 사라집니다 (`dynamic = "force-dynamic"` + `Cache-Control: no-store`).
- DB에 남는 건 얼굴형·비율 같은 **파생 숫자**뿐이고, 그것도 주문을 확정할 때만 기록됩니다.
  마법사 진행 중 상태는 localStorage에도 넣지 않고 메모리에만 둡니다.
- 처방 도수는 개인정보보호법상 **민감정보**입니다. 안경원에 전달할지는 예약 단계에서 별도
  동의를 받고(`sensitiveConsent`), 동의하지 않으면 아예 저장하지 않습니다.
- 공장에는 설계 치수만 전달되고, 도수와 연락처는 전달되지 않습니다.
- 얼굴 분석 프롬프트는 외모 평가·매력도 점수·인종/성별/나이 추정을 금지하고, 안경 사이즈
  계산에 필요한 기하학적 비율만 뽑도록 제한했습니다.
- 아이핏은 의료기기가 아니며 진단·처방을 하지 않습니다. OCR로 읽은 도수는 "매장에서
  확인할 초안"이지 확정 처방이 아닙니다.

## 기술 스택

Next.js 14 (App Router) + TypeScript + Tailwind CSS / Prisma + PostgreSQL /
OpenAI 비전 모델(얼굴 비율 측정, 처방전 판독)

## 로컬 개발

```bash
cd eyefit
npm install
cp .env.example .env       # OPENAI_API_KEY를 실제 키로 채우기 (서버에서만 사용)

docker compose up -d       # 로컬 Postgres (localhost:5433, 하브루타 톡의 5432와 안 겹침)
npm run db:push            # 스키마 반영
npm run dev                # http://localhost:3000
```

OpenAI 키가 없어도 앱은 죽지 않습니다. 얼굴형을 직접 고르고 도수를 직접 입력하는 경로로
끝까지 진행할 수 있습니다.

## 배포 (Vercel)

하브루타 톡과 **별개의 Vercel 프로젝트**로 만듭니다.

1. [vercel.com/new](https://vercel.com/new)에서 `choiyeonah-hub/yeonah` 저장소를 Import.
2. **Root Directory를 `eyefit`으로 지정**합니다. (이게 두 앱을 나누는 핵심 설정입니다.)
3. Settings → Environment Variables에 아래를 등록합니다.
   - `POSTGRES_PRISMA_URL`
   - `POSTGRES_URL_NON_POOLING`
   - `OPENAI_API_KEY`
   - `OPENAI_VISION_MODEL` (선택)
4. Deploy. 테이블은 따로 만들 필요 없습니다 — `vercel-build`가 매 배포마다
   `prisma db push`를 실행해 스키마를 맞춰줍니다.

> DB는 하브루타 톡과 **다른 데이터베이스**를 쓰세요. 두 프로젝트의 Prisma 스키마가
> 서로 다르고, `prisma db push --accept-data-loss`가 상대 테이블을 지울 수 있습니다.
