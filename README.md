# 하브루타 톡 — 가족 질문 대화 앱

바쁜 하루에도 아이와 눈을 마주치고 대화할 수 있도록, ChatGPT(OpenAI API)가 오늘 있었던 일에서
꼬리에 꼬리를 무는 하브루타 질문을 대신 만들어주는 가족용 웹 앱입니다.

## 핵심 기능

- **채팅형 인터페이스**: 가족이 오늘 있었던 일을 입력하면, AI가 그 내용을 이어받아 다음 질문을
  하나씩 만들어줍니다. 화면 상단에는 "지금 이 질문"이 큰 카드로 뜨는데, 이건 채팅을 보라는 게
  아니라 **그 질문을 함께 읽고 눈을 마주치며 이야기 나눈 뒤, 그 대화 내용을 채팅창에 기록**하라는
  용도입니다.
- **가족 연동**: 가족 코드(6자리)로 여러 기기에서 같은 가족 대화방에 참여합니다. 부모/아이 여러 명이
  같은 하루 세션에 이야기를 남길 수 있습니다.
- **나이대별 질문 층위**: 태어난 연도로 나이대(유아/어린이/초등고학년/청소년/성인)를 계산하고,
  나이대에 맞는 질문 깊이 범위 안에서 AI가 질문을 만듭니다.
- **질문 층위 점수화**: 하브루타 질문을 5단계 사다리로 분류합니다.
  1. 사실 확인 → 2. 감정 탐색 → 3. 이유 탐구 → 4. 상상·가정 → 5. 가치·적용
  대화가 이어질수록 한 단계씩 깊어지도록 유도하고, 오늘의 평균 깊이 / 누적 질문 수 /
  연속 대화 일수를 통계로 보여줍니다.
- **오늘 얘깃거리가 없을 때**: "오늘 얘깃거리가 없어요" 버튼을 누르면 AI가 무작위 그림 주제와
  그 그림으로 시작하는 첫 질문을 만들어줍니다(이미지 생성 실패 시에도 질문은 정상 진행).
- **지난 기록**: 채팅 중심 UI를 유지하면서도, 지난 날짜별 대화를 목록으로 훑어보고 다시 읽을 수
  있는 가벼운 기록 페이지를 제공합니다.

## 기술 스택

- Next.js 14 (App Router) + TypeScript + Tailwind CSS
- Prisma + PostgreSQL (가족/구성원/일별 세션/메시지) — Vercel 같은 서버리스 배포에서는
  로컬 파일(SQLite)이 재배포마다 초기화되기 때문에 Postgres를 씁니다.
- OpenAI API (`gpt-4o-mini`로 질문 생성, `gpt-image-1`로 무작위 주제 이미지 생성).
  생성된 이미지는 서버리스 환경이 디스크에 못 쓰므로 base64로 DB에 바로 저장합니다.
- 로그인은 별도 회원가입 없이 "가족 코드 + 닉네임"만으로 참여하는 경량 방식입니다
  (localStorage에 신원을 저장). 더 강한 보안이 필요하면 NextAuth 등으로 교체하세요.

## 로컬 개발

계정 가입 없이 바로 개발하려면 docker로 로컬 Postgres를 띄우세요.

```bash
npm install
cp .env.example .env
# .env 에 OPENAI_API_KEY 를 실제 키로 채워주세요 (서버에서만 사용, 브라우저에 노출되지 않음)

docker compose up -d   # 로컬 Postgres (localhost:5432, .env.example 기본값과 일치)
npm run db:push         # 스키마 반영
npm run dev              # http://localhost:3000
```

Neon/Vercel Postgres 같은 클라우드 DB를 로컬에서 바로 쓰고 싶다면, docker 없이
`.env`의 `POSTGRES_PRISMA_URL` / `POSTGRES_URL_NON_POOLING`만 그 DB 주소로 바꾸면 됩니다.

## 배포하기 (Vercel)

로또추첨기(260711)와 같은 방식으로, Vercel에 GitHub 저장소를 연결해서 배포합니다.
(이 코드를 만든 세션은 vercel.com에 대한 아웃바운드 접속이 막혀 있어서 CLI로 직접
배포는 못 하고, 아래 순서대로 대시보드에서 클릭 몇 번이면 끝나게 준비해뒀어요.)

1. **저장소 임포트**: [vercel.com/new](https://vercel.com/new) → `choiyeonah-hub/yeonah`
   저장소 선택 → Import. (Framework는 Next.js로 자동 인식됩니다.)
2. **Postgres 준비**: Vercel의 Storage 연동을 써도 되고(있다면), 아니면
   [neon.tech](https://neon.tech)에서 무료로 DB를 하나 만들어서 나오는
   **Connection string**을 그대로 써도 됩니다.
3. **환경변수 등록**: 프로젝트 **Settings → Environment Variables**에서 아래 세 개를
   추가합니다 (Production 체크). Neon처럼 연결 문자열이 하나뿐이면 두 값에 똑같이
   넣으면 됩니다.
   - `POSTGRES_PRISMA_URL`
   - `POSTGRES_URL_NON_POOLING`
   - `OPENAI_API_KEY`
4. **Deploy** 클릭. **테이블은 따로 만들 필요 없습니다** — `package.json`의
   `vercel-build` 스크립트가 빌드할 때마다 `prisma db push`를 자동으로 실행해서
   스키마를 최신 상태로 맞춰줍니다(Vercel이 이 스크립트를 자동으로 감지해서 씁니다).
   이후로는 `claude/habruuta-chatgpt-app-81uq8q` 브랜치(또는 main)에 푸시할 때마다
   자동 재배포되고, 그때마다 스키마도 같이 동기화됩니다.

> 이미지 생성 기능을 쓰려면 OpenAI 계정에 `gpt-image-1` 사용 권한이 있어야 합니다.
> 권한이 없어도 앱은 죽지 않고, 그림 없이 질문만 정상적으로 생성됩니다.
>
> `vercel-build`는 `prisma db push --accept-data-loss`를 씁니다. 이후 스키마를 바꿀 때
> 컬럼을 지우거나 타입을 바꾸는 등 파괴적인 변경이 있으면 데이터가 조용히 사라질 수 있으니,
> 실제 가족 데이터가 쌓인 뒤에 스키마를 바꿀 땐 이 부분을 참고하세요.

- 이미지 생성(`gpt-image-1`)은 계정에 따라 별도 인증이 필요할 수 있습니다. 실패해도 앱은

# AI 퍼스널컬러 · 체형 스타일링 (`/style`)

같은 레포 안에 있는 두 번째 앱입니다. 하브루타 톡은 `/`, 스타일 진단은 **`/style`** 에서 열립니다.

얼굴 사진에서 **피부·모발·눈동자 색을 뽑아 12타입 퍼스널컬러**를 진단하고, 전신 사진이나 직접 잰
치수에서 **얼굴 길이·다리 길이·팔 길이 비율**을 계산해서, 옷·구두·가방을 **HEX 색값과 cm 수치까지**
찍어 추천합니다.

## 무엇을 해주나

1. **퍼스널컬러 12타입 진단** — 봄/여름/가을/겨울 × 라이트·브라이트·뮤트·딥·웜·쿨
   - 사진 속 색을 CIE Lab으로 변환한 뒤 **웜·쿨 / 명도 / 채도 / 대비** 네 축 좌표로 환산하고,
     12타입 좌표와의 거리로 1순위·2순위와 확신도(%)를 냅니다.
   - 피부의 웜·쿨은 색상각이 아니라 **Lab의 b*(노랑) ÷ a*(빨강) 비율**로 봅니다. 사람 피부는
     전부 주황 계열이라 색상각만으로는 갈리지 않기 때문입니다.
   - 한국인 대부분이 검은 모발이라 대비가 전원 100점으로 몰리는 문제, 피부 L*이 55~90에만
     분포해 딥 계열이 선택되지 않는 문제는 각각 **실제 분포대를 0~100으로 펴서** 보정했습니다.
   - 사진이 없으면 **10문항 문진**으로 같은 네 축을 채웁니다(사진과 문진이 둘 다 있으면 7:3으로 섞음).
   - AI가 읽은 색이 실제와 다르면 화면에서 **직접 색을 고칠 수 있습니다**.
2. **몸 비율 진단** — 두신 비율, 얼굴 길이 비율, 다리 길이 비율, 상체:하체, 팔 길이 비율,
   어깨:엉덩이, 허리:엉덩이(WHR)를 한국 성인 평균대와 비교해 보여줍니다.
   체형 5분류(모래시계 / 일자 / 하체 볼륨 / 상체 볼륨 / 복부 볼륨)와 골격 3분류(스트레이트 ·
   웨이브 · 내추럴)도 함께 나옵니다. 안 잰 항목은 키·성별 평균으로 추정하고 **(추정)으로 표시**합니다.
3. **색값 상세** — 팔레트의 모든 색을 누르면 HEX / RGB / HSL / CIE Lab / LCh / CMYK 값이 펼쳐집니다.
   그대로 복사해서 쇼핑몰 검색이나 원단·페인트 주문에 쓸 수 있습니다.
4. **내 몸에 맞는 cm 수치** — 굽 높이, 팬츠 밑단 위치, 상의 총장(크롭/레귤러/롱),
   스커트 총장(무릎 위/미디/롱), 아우터 총장, 가방 가로 사이즈, 크로스백 스트랩 길이를
   키와 비율에서 직접 계산합니다. 예를 들어 굽 높이는 *(이상 다리 비율 47% − 내 다리 비율) × 키 × 0.6*
   로 구한 뒤 신을 수 있는 범위로 제한합니다.
5. **옷 · 구두 · 가방 추천** — 체형 × 골격 × 비율 × 퍼스널컬러 조합으로 아이템·소재·기장·색을 함께 제시하고,
   데일리 / 오피스 / 특별한 날 **코디 3세트**를 만들어 줍니다.
   구두의 "누드 컬러"는 팔레트가 아니라 **내 피부색에서 계산한 값**(피부보다 살짝 어두운 톤)입니다.
6. **AI 스타일리스트 코멘트** — 위 계산 결과를 근거로 쇼핑할 때 확인할 것들을 요약합니다(선택).

## 화면

- `/style` — 진단 마법사(퍼스널컬러 → 키·비율 → 골격) + 결과
- `/style/result/[id]` — 저장된 결과 다시 보기 / 공유 링크

## API

| 메서드 | 경로 | 설명 |
| --- | --- | --- |
| `POST` | `/api/style/vision` | `kind: "face"`면 사진에서 피부·모발·눈동자·입술 HEX 추출, `kind: "body"`면 전신 사진에서 비율 추정 |
| `POST` | `/api/style/analyze` | 진단 + 추천 계산(+ AI 코멘트), Postgres가 있으면 결과 저장 |

## AI를 쓰는 곳과 안 쓰는 곳

**진단과 추천 계산은 전부 결정적(deterministic) 코드입니다.** AI는 세 곳에만 씁니다.

- 얼굴 사진 → 색 측정 (`gpt-4o-mini` 비전)
- 전신 사진 → 비율 추정 (비전)
- 결과 요약 코멘트 (텍스트)

그래서 `OPENAI_API_KEY`가 없어도 **문진 + 직접 측정**으로 앱 전체가 정상 동작합니다.
같은 입력이면 항상 같은 결과가 나오고, AI가 팔레트에 없는 색을 지어낼 수 없습니다.

## 실행

하브루타 톡과 같은 프로젝트라 실행 방법도 같습니다(위 "로컬 개발" 참고).
`POSTGRES_PRISMA_URL`이 없으면 결과 저장·공유 링크만 빠지고 진단은 그대로 됩니다.

```bash
npm install
npm run dev            # http://localhost:3000/style
```

## 내 옷장 (`/style/closet`)

가진 옷을 등록하면 진단 결과를 기준으로 하나씩 판정합니다.

- **색 판정** — 옷 색과 팔레트 사이의 거리를 **CIE Lab ΔE**로 재서 `베스트 / 무난 / 주의` 3등급을 냅니다.
  "왜 주의인지"까지 숫자로 보여줍니다(예: *피해야 할 색인 카멜(#B07B3E)에 더 가깝습니다 — ΔE 0.0 vs 베스트 42.2*).
- **기장 판정** — 등록할 때 총장·굽 높이·가방 가로를 넣으면 내 키에서 계산한 권장 수치와 비교합니다.
  특히 **종아리가 가장 굵은 구간에서 끝나는 치마 기장**을 잡아냅니다(키의 20.5~25% 높이 구간에서 역산).
- **옷 사진 색 자동 인식** — 사진의 가운데 60%만 보고 색을 양자화·군집해 대표 색 3개를 뽑습니다.
  **AI를 부르지 않습니다**(옷 색은 사진에 그대로 있으므로 모델이 필요 없습니다). 고른 색은 직접 고칠 수 있습니다.
- **내 옷장으로 만든 코디** — 색 점수 + 기장 적합도 + 위아래 색 조화를 합산해 실제로 가진 옷들의 조합을 만듭니다.
  다리 비율이 짧게 나온 사람에게는 *하의와 신발의 ΔE가 가까운 조합*에 가산점을 줍니다.
- 옷 사진과 목록은 **서버로 보내지 않고 브라우저(localStorage)에만** 저장됩니다. 계정이 없는 앱이라 그게 가장 안전합니다.
  대신 기기·브라우저를 옮기면 옷장은 따라오지 않습니다.

## 아직 없는 것 (그리고 왜 없는지)

- **실제 상품 링크·재고 연동** — 기술이 아니라 제휴 계약 문제입니다. 쿠팡 파트너스 검색 API는 시간당 10회·상품 10개
  제한이 있고, 네이버 쇼핑 검색 API는 2026년 종료됐습니다. 재고는 판매자 계약 없이는 받을 수 없습니다.
- **가상 피팅** — 외부 try-on API(이미지당 약 $0.04~0.075)를 붙이면 가능하지만, 입어볼 상품의 정면 누끼 이미지가
  따로 필요합니다.

## 한계

- 사진 진단은 **조명과 화이트 밸런스**의 영향을 받습니다. 자연광에서 화장기 없이 찍은 정면 사진이
  가장 정확하고, 실내 노란 조명에서는 웜으로 치우칠 수 있습니다.
- 전신 사진 비율 추정은 카메라 각도·자세에 따라 오차가 있습니다. 정확한 결과를 원하면 직접 잰
  치수를 입력하세요(사진 결과도 화면에서 수정할 수 있습니다).
- 퍼스널컬러는 절대적인 판정이 아니라 **참고 기준**입니다. 확신도가 낮게 나오면 2순위 타입의
  팔레트도 함께 비교해 보세요.
